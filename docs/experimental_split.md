# Experimental split (train / internal-validation / test)

Defines the reproducible, **patient-level** experimental split used for all
modeling. It is generated by [`scripts/build_splits.py`](../scripts/build_splits.py)
and written to `data/splits/{train,internal_val,test}.csv` + `split_summary.json`.

> No models are trained here and no metrics are computed. This step only assigns
> images to splits and verifies there is no leakage.

## Core methodological guarantees

1. **The official CheXlocalize TEST set is untouched.** `test.csv` is the 668
   official test images verbatim (500 patients). It is **not** produced by
   sampling the 902 images and is never mixed into train/internal_val.
2. **The official VALIDATION set (234 imgs / 200 patients) is the development
   pool**, split into `train` / `internal_val`.
3. **Patient-level split.** Images are grouped by `patient_id`; a patient's
   images go entirely to one side. No patient appears in both train and
   internal_val.
4. **Negatives are kept.** Images with no non-empty segmentation are included in
   the dev split (not discarded) and cross-checked against CheXpert labels.
5. **Read-only sources.** Nothing in `data/raw/` is modified.

## Split configuration (reproducible)

From [`configs/project.yaml`](../configs/project.yaml) → `split`:

| Setting | Value |
| --- | --- |
| `seed` | **42** |
| `level` | patient |
| `dev_pool` | official `val` |
| `benchmark` | official `test` (untouched) |
| `train_fraction` | 0.8 (by images, patient-grouped) |

## Exact splitting procedure

1. Load the official image lists from `CheXpert/val_labels.csv` (234) and
   `CheXpert/test_labels.csv` (668); derive `image_id` = `patient_study_view`
   and `patient_id` from each `Path`.
2. `test.csv` ← all 668 official test images (verbatim benchmark).
3. Group the 234 validation images by patient (200 patients).
4. Shuffle patients with `random.Random(42)`.
5. Add patients to **train** until cumulative train images reach
   `round(0.8 × 234) = 187`; assign all remaining patients to **internal_val**.
   Because assignment is per patient, the two sides are patient-disjoint by
   construction.
6. For every split image × 10 canonical pathologies, emit a row joining the
   decoded-mask manifest (`data/processed/manifests/manifest.csv`) and the
   original CheXpert label (`chexpert_label`).

## Results (seed = 42)

| Split | Patients | Images | Positive imgs | Negative imgs | Rows |
| --- | --- | --- | --- | --- | --- |
| train | 161 | 187 | 145 | 42 | 1,870 |
| internal_val | 39 | 47 | 42 | 5 | 470 |
| **test (official)** | 500 | 668 | 499 | 169 | 6,680 |

- Dev pool totals: **200 patients / 234 images** (161+39 patients, 187+47 images).
- Actual train image fraction: **0.7991** (≈ 80 %).
- "Positive image" = has ≥ 1 non-empty GT mask; "negative" = none.

Each row contains: `image_id, patient_id, split, image_path, pathology,
mask_path, has_mask, csv_alias, chexpert_label`.

## Proof: no patient in both train and internal_val

Check **A** computes `train_patients ∩ internal_val_patients` and asserts it is
empty. Result: **0 overlapping patients** (`split_summary.json →
patient_overlap_train_ival: []`). This is also guaranteed structurally, since
assignment is performed on whole patients.

## Proof: official test set kept separate

- `test.csv` is built only from `test_labels.csv` (official test list), never by
  random sampling.
- Check **B**: `test_image_ids ∩ train_image_ids = ∅` → PASS.
- Check **C**: `test_image_ids ∩ internal_val_image_ids = ∅` → PASS.
- The test patients (`patient647xx…` range, 500 patients) are disjoint from the
  validation patients by CheXpert construction.

## Pathology naming (canonical)

- Canonical pathology name remains **"Airspace Opacity"** in all split CSVs
  (check **F**).
- **"Lung Opacity"** appears **only** in the `csv_alias` column, and only for
  `Airspace Opacity` rows (check **G**). Nothing was renamed in place.

## Negative-label cross-check (requirement 9)

For every `has_mask = False` (image, pathology) pair we compare against the
original CheXpert label. Pairs where the label is positive (`1.0`) yet no pixel
mask exists are reported (they are **informational, not failures** — CheXlocalize
only provides masks where a radiologist localized the finding):

| Split | conflicting pairs |
| --- | --- |
| train | 0 |
| internal_val | 1 |
| test | 6 |

The exact pairs are listed in `split_summary.json →
negative_label_cross_check.conflict_pairs` (e.g. internal_val:
`patient64612_study1_view1_frontal / Airspace Opacity`). All other negatives are
confirmed non-positive in the CheXpert labels.
